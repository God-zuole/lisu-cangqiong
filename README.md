# 小说工作区 · 使用说明

> 底层工作流来自开源项目 **dashenbibi/novel-master v1.3.0**（MIT）。
> 核心思想：**工作区优先**——所有设定、状态、伏笔都存在本地 Markdown 文件里，AI 每次写作前先读文件，而不是凭想象续写。
> 这样写几百万字，前后才不会打架。

## 每次写作前，AI 必读顺序

```
rules.md → 故事架构.md → 00-overview.md → 02-world/ → 01-characters/ → 03-volumes/ → 05-tracker/
```

读完后必须先输出摘要（主线目标 / 当前卷阶段目标 / 关键角色动机 / 世界规则 / 已登记伏笔），再动笔。

---

## 一套完整的章节循环

1. **骨架**：标题、视角、核心冲突、5-8 个剧情节点、章末钩子
2. **正文**：只按骨架扩写，不擅自改主走向（2200-3000 字）
3. **润色**：去 AI 味、抽象情绪改动作、收紧对话
4. **质检**：先报问题再改，输出「问题点 / 证据段落 / 修正建议」
5. **同步**：把角色状态、境界变化、伏笔增删写回 `05-tracker/` 与 `00-overview.md`

## 常说的话（指令模板）

```
生成第 X 章骨架，包含开场锚点、核心冲突、关系变化点、认知变化点、章末钩子
按骨架扩写第 X 章正文到 2200-3000 字
润色第 X 章，重点检查 AI 味、对话、战力是否越级
检查第 X-Y 章一致性，只列问题不改文
检查所有伏笔的回收状态，列出已埋未收
更新角色状态，把第 X 章的变化写回档案和追踪表
```

---

## 硬性红线（写每章都要过一遍）

1. **不得新增力量体系**，全书只有微观结构改写
2. **不得越级**，境界能力对照 `故事架构.md` 第三节硬卡
3. **不得玄学化**，禁用词清单见 `rules.md` 第二节
4. 每章必须有：推进点 ≥1、关系变化点 ≥1、认知变化点 ≥1、冲突 ≥1、章末钩子 ≥1
5. 正文不得留任何 `[待填]` 占位符
